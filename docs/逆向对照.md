## 三、视频助手

### 3.1 任务点扫描

**逆向来源**：`brushCx.ac53035b.js`（超星任务扫描器）

原实现枚举两类「需要处理的任务」：

- (a) 任何 `iframe`，**不在** `.cmd-autoblockquote` 内，且 `src` 含 `/ananas/modules/` 或 `/ananas/dialog/ballchart`
- (b) 任何 `.blockquote-wrap`，含 `.cmd-autoblockquote`，且有 `.ans-blockquote-handle` 或内嵌 iframe

每项写 `data-dx-task-id`，然后：

```js
window.postMessage({ type: "cxTypes", data: { route, tasks } }, "*")
// task = { id, source: "iframe"|"blockquote", order, iframeIndex, src, blockIndex? }
// route = { href, mainIframeSrc, mainDocumentHref }
```

等待策略按网络类型：`slow-2g/2g → 15s`，`3g → 8s`，否则 `2s`。

**本复刻**：`src/adapter/task-scan.js`（逐条复刻，含 debounce 500ms、run token、MutationObserver + history 钩子 + 1s 兜底轮询、按 route 指纹去重）。

### 3.5 播放与倍速

**逆向来源**：`../../dom/videoDom` 的 `p()`（@13534249）、`executeVideoTask`（@13538470 / @13539101 / @13540050）、`taskStateGateway.getPlaybackRate`（@13482416）、SideBar 面板的 `onMounted`（@5356800）与 `handleSelectRate`（@5359689）、background 的 `GetPlaybackSpeed` 分支（`index.js.pretty.js` @78223）。

**倍速机制（已完全定位，早期「未定位」的结论已作废）：**

1. `../../dom/videoDom` 的播放器封装同时负责静音与倍速：

```js
let p = async (e, r) => {
  (e.muted = !0), (e.playbackRate = r);
  try { let r = e.play(); r && ... } catch { ... }
};
```

2. 倍速值来自 `taskStateGateway.getPlaybackRate()`：

```js
L = () => { let e = Number(l.brushState.playbackRate); return Number.isFinite(e) && e > 0 ? e : 1 };
```

3. 调用点：任务开始 `await p(F, getPlaybackRate())`（@13538470）；循环里每秒重申 `F.playbackRate = getPlaybackRate()`（@13539101 / @13539125）；暂停恢复时再次 `await p(F, getPlaybackRate())`（@13540050）。

4. **初始倍速的来源是超星自己的 `doubleSpeedValue` cookie**（这就是早期按 `doubleSpeed` 搜不到的原因 —— 真实名字带 `Value` 后缀）：

```js

      t = e.find((e) => "doubleSpeedValue" === e.name);

  return;
}
// SideBar 面板 onMounted（@5356800）：cookie 优先 → 存储 playBackRate → "1"
if (o.isChaoXingStudy) {

      r = e?.speed?.value || s || "1";        // s = await storage.get("playBackRate")

```

5. 用户在面板里改倍速（@5359689）：立刻写当前视频元素 `videoEl.value.playbackRate = +e.value`，更新 `brushState.playbackRate`，并 `storage.set("playBackRate", e.value)`。

6. `videoplayrate.4e59ba0f.js`（MAIN world）**只做反检测，不设倍速** —— 见 3.6。

**本复刻的实现**：与上述 1/2/3/5 一一对应 ——

1. `src/content/side-bar.js` 的 `applyRate(media, iframe)` 设置 `media.muted` 与 `media.playbackRate`，并在 `driveVideo` 的 1s 循环里重申；
2. `src/adapter/video-rate.js` 在视频 iframe 内维护一个「倍速看门狗」，收到 `{type:"dxSetPlaybackRate"}` 后持续把页面内所有 `video/audio` 纠正到目标倍速，并监听 `play` 事件覆盖新出现的元素（比原插件的「每 1s 重申」更稳，**这一点是有意增强，不是臆造**）；
3. 倍速值存 `playBackRate` 语义等价键；面板一改就写入存储并立刻生效；
4. **`doubleSpeedValue` cookie 也实现了**：新增 `GetPlaybackSpeed` 消息，background 用 `chrome.cookies.getAll({domain:"chaoxing.com"})` 找 `doubleSpeedValue`，内容脚本在初始化时若用户尚未显式设过倍速（仍为默认 1）就采用它，并在日志里注明来源。因此需要 `cookies` 权限（与原插件一致）。

返回串**只有**这 6 种：`未找到提交按钮`、`未检测到提交结果弹窗`、`未做完`、`未及格`、`全部通过`、`提交错误`。

**本复刻**：`src/content/side-bar.js` → `tmpSave()`、`submitAll()`（同选择器、同返回串、同网络等待策略），并把「不安全就不自动提交」做成策略：**只有全部题都确认填充成功才自动提交，否则自动降级为「暂存」** —— 这是原插件的 `allSafe` 思路，本复刻保留。

## 六、本地答案题库（原插件**没有**的净增能力）

**为什么加**：逆向确认原插件**每道题都必须请求自己的服务器**（`/dxai/submit/exercise/solve`，见 §五），
没有任何本地复用层。用户在 m01043 明确表示不愿消耗自己的 API 额度，因此本复刻增加一层本地题库：
命中即秒答、零花费、零等待。

**这不是逆向结论，是自建设计**，此处登记以免与"复刻"混淆。

### 6.1 题目身份（key 派生）

`src/background/cache.js` → `cacheKey(payload)`，按可靠性降序取第一可用者：

| 优先级 | 条件 | key 形状 |
| --- | --- | --- |
| 1 | 有 `questionId` | `id:<去空白后的题号>|<题型>` |
| 2 | 有题干或选项 | `txt:md5(题型 \0 题干 \0 选项.join("\x01"))` |
| 3 | 有图片 | `img:md5(题型 \0 base64 \0 选项)` |
| — | 都没有 | `""` ⇒ 不读不写题库 |

**为什么把题型与选项一起折进哈希**：只用题干不够 —— 同一句题干在不同课程/不同题库里
选项可能不同（"下列说法正确的是"这类模板题干尤其明显），只用题干会串答案。

`normalizeForKey()` 去掉 `[\s\u00a0\u3000]+` 与零宽字符 `[\u200b-\u200f\ufeff]`，
所以题干里的排版空白差异、`&nbsp;`、零宽字符不会造出重复条目。

### 6.2 存储与淘汰

`chrome.storage.local` 键 `dxrep_answerCache`（`CACHE_STORAGE_KEY`），形状：

```js
{ v: 1, meta: { hits, miss }, entries: { "<key>": { o, t, e, n, at } } }
// o = 答案  t = 题型  e = 产生它的引擎  n = 命中次数  at = 最后使用时间戳
```

上限 `MAX_ENTRIES = 20000`；超出后 `trimEntries()` 按 `at` 升序淘汰最旧的，
保留 `floor(max * 0.9)` 条（留余量，避免每加一条就淘汰一次）。

### 6.3 读写时机（`src/background/index.js` → `handleSolve`）

- **读**：仅在 `useCache === true` 时先 `cacheGet(key)`，命中直接返回
  `{ errNo:0, result:{ option, isAccurate:1, engine:"cache", fromCache:true, questionType } }`
  —— **不发任何网络请求**。
- **写**：只要 `errNo === 0` 且拿到的 `option` 非空就 `cachePut(...)`，
  **不受 `useCache` 开关影响**。理由：用户可能临时关掉"用旧答案"，
  但题库应继续积累，下次打开就有货。
- `cacheGet` 命中时 `n++`/`at = now`/`meta.hits++`；未命中 `meta.miss++`。
  命中率显示在设置页，用来判断这层到底省了多少次引擎调用。

### 6.4 导入 / 导出 / 合并

设置页「本地题库」一节：导出为 `网课助手题库-<时间戳>.json`；导入走 `FileReader` →
`JSON.parse` → `CACHE_IMPORT`。

`mergeEntries(base, incoming)` 的语义（已自测）：

- **以导入的答案为准**（同一条目答案不同时用对方的）—— 假定同学那份更新。
- 保留两者中较大的 `n` 与较新的 `at`（不因为合并而"丢失使用历史"）。
- 只接受 `o` 为非空字符串的条目，其余计入 `skipped`。
- 返回 `{ entries, added, updated, skipped }` 并在设置页显示，让用户知道合并了什么。
- **不改动入参对象**（纯函数），便于测试与重试。

所有题库操作都经 background 单点写，避免设置页与 service worker 并发改同一键丢更新。

### 6.5 自测覆盖

`test/logic.test.mjs` 第 5 节覆盖：key 三条优先级的正反例、
题干空白/全角/零宽归一、选项顺序敏感性、LRU 淘汰边界与"最久未使用被淘汰"、
导入合并的 added/updated/skipped 计数与"以导入为准"语义、
以及 background/solver/options 的接线断言。全套自测当前 **203 项全过**；
中转端另有 `test/relay.e2e.mjs` **35 项全过**（含「上游返回 400 时自动去掉
`response_format` 重试」与「中转/扩展题库 key 算法逐项一致」）。

## 七、答案来源分派与「答题中转」（原插件**没有**的净增能力）

### 7.1 为什么需要这一层

逆向结论（§五）表明：原插件的「下载即用」并不是它代码的功劳，而是**它替你养了一台服务器**——
`/dxai/submit/exercise/solve` 跑在 `www.daxuesoutijiang.com` 上，算力由他们出，靠 VIP 收费。

> 这也解释了原插件为什么能零配置：视频助手是纯本地 DOM 操作（不需要服务器），
> 而解题助手的算力**不在 CRX 里，掏不出来**。

本复刻因此把「答案从哪来」显式拆成四路，由 `SK.ANSWER_SOURCE` 选择；
用户只要自己扮演一次原插件那台服务器的角色（架一次中转），
之后**打包发出去就是零配置**。

### 7.2 四路分派（`src/background/index.js` → `handleSolve`）

顺序固定：**先查本地题库 → 未命中再按来源分派**。

| `answerSource` | 走哪个求解器 | 需要的配置 | 适用场景 |
| --- | --- | --- | --- |
| `bank`（**默认**） | 无 | 无 | 零依赖、不联网。查不到就返回 `errNo -100` 安静跳过 |
| `relay` | `solveWithRelay` | 中转地址（+ 可选口令） | **分享给同学**：对方装完就可用 |
| `llm` | `solveWithLlm` | API 地址 + 模型名 | 自己用；填本机 Ollama 可完全免费离线 |
| `origin` | `solveWithOrigin` | 该站账号权益 | 忠实还原本复刻逆向到的原链路 |

源码顶部两个常量把这套约定收成一处，**分享前只改这一行**：

```js
const DEFAULT_RELAY_URL = "";              // 改成你的答题中转地址
const DEFAULT_ANSWER_SOURCE = "bank";      // 分享时改成 "relay"
```

四路都没有可用配置时统一返回
`{ errNo:-100, noEngine:true, errMsg:"…" }`，由内容脚本的
`isNoEngine()` / `notifyNoEngine()`（`src/content/side-bar.js`）
只提示一次然后跳过该题 —— **不刷日志、不算失败**。
三处调用点均已接入：`side-bar.js:845`（视频弹题）、`side-bar.js:1032`（学习页内嵌测验）、
`side-bar.js:1772`（独立考试页）。

### 7.3 中转契约（`server/answer-relay.mjs`）

单文件、零依赖、仅用 Node 标准库，因此可以整份丢到任何一台有 Node 的机器上。

| 路由 | 用途 |
| --- | --- |
| `GET /health` | 返回 `{ ok, model, mode, needToken, bank }`，供设置页「测试中转」 |
| `GET /bank.json` | 导出中转题库，可给扩展导入 |
| `POST /bank` | 合并导入 `{ token?, entries }` → `{ added, updated, skipped, total }` |
| `POST /solve` | 主接口 |

`POST /solve` 请求体 `{ token?, payload }`（`payload` 与扩展内 `buildPayload` 同构）；
响应体与扩展内部结果一致：

```json
{ "errNo": 0, "result": { "option": "B", "isAccurate": 1, "questionType": "单选题", "engine": "relay-llm" } }
```

`engine` 取值：`relay-bank`（中转自己的题库命中）/ `relay-llm`（现算的）。

上游调用（`callUpstream`）复刻了扩展端同一套
`SYSTEM_PROMPT` / `buildUserText` / `extractJson` / `normalizeAnswer`，
并带一个**兼容性回退**：若上游返回 HTTP 400 且原本开了 `response_format:{type:"json_object"}`，
自动去掉该字段重试一次（兼容不吃 JSON mode 的中转/推理模型）。

**题库 key 算法与 `src/background/cache.js` 逐项一致**
（`id:<去空白题号>|<题型>` / `txt:md5(题型\0题干\0选项)` / `img:md5(题型\0图\0选项)`，
md5 走 `node:crypto`），所以**中转载下的题库能直接导入扩展，反之亦然** ——
这条一致性由 `test/logic.test.mjs` 与 `test/relay.e2e.mjs` 双重断言。

落盘用 2 秒防抖 + `.tmp` → `rename` 原子替换，`SIGINT` 时保存退出；
`MAX_BODY_BYTES = 32MB`、`MAX_ENTRIES = 20000`，超限时保留最新的 90%。

## 八、与原插件的有意差异

| # | 原插件 | 本复刻 | 理由 |
| --- | --- | --- | --- |
| 1 | 9 个适配器由 background 用 `chrome.scripting.registerContentScripts` 以 `world:"MAIN"` 运行时注册 | 直接写进 `manifest.content_scripts` 的 `world:"MAIN"` | 更简单、更稳、易审计；要求 Chrome 111+ |
| 2 | 答题固定走自己服务器 | **四路可插拔**：`bank`（默认）/ `relay` / `llm` / `origin`，一键切换 | 用户指定不可花自己的钱、且要能分享 |
| 3 | 支持 7 个平台 | 只做超星 | 用户指定 |
| 4 | 截屏搜题 / 划词翻译 / AI 对话 | 全部剔除 | 用户指定 |
| 5 | 题目截图用 `html2canvas` 整题渲染 | 滚动到题目 + `chrome.tabs.captureVisibleTab` 可视区截图 | 去掉 ~50KB 依赖，视觉模型输入效果等价 |
| 6 | 字体混淆用 Typr + 静态 md5 表还原 | 含图/混淆时直接走截图 | 表会随平台更新失效，截图天然免疫 |
| 7 | 存储前缀 `college_ai_` | `dxrep_` | 避免与原插件同装时互相覆盖 |
| 8 | 提交策略由 `allSafe` 决定 | 同样 `allSafe`：**不安全就自动降级为暂存** | 避免误交，属安全默认 |
| 9 | 倍速由 `dom/videoDom` 的 `p()` 设置并每 1s 重申；初始值取 `doubleSpeedValue` cookie → `playBackRate` 存储 → `"1"` | 同机制复刻，另加 `video-rate.js` 的 `play` 事件看门狗（新出现的媒体元素也立刻纠正） | b16 早期「原插件不设倍速」的结论**已作废**（漏搜 `doubleSpeedValue` 后缀）；看门狗是有意增强 |
| 10 | 独立考试/作业页用 `html2canvas` 截图，且**不自动提交** | 用 `captureVisibleTab`，同样不自动提交 | 与差异 #5 一致；用户诉求即「可直接填充」 |
| 11 | 原插件把题目内容与截图上报自家服务器（`SaveExcise` / `QUESTION_SOLVE` 等） | 只写本地日志，不上报 | 隐私；仅在使用 `origin` 引擎时才发出必要请求 |
| 12 | 每道题都必须请求服务器，**没有本地复用层** | 增加本地答案题库（命中零请求）+ 导入/导出/合并 | 用户指定不愿消耗自己的 API 额度；详见 §六 |
| 13 | 「下载即用」依赖**它自己养的服务器**（算力不在 CRX 里，掏不出来） | 把这台服务器的角色交给用户：新增 `server/answer-relay.mjs`，架一次即可让所有人零配置；答案来源变为四路可插拔，默认最保守的 `bank` | 用户要求**可分享给同学、对方零配置**；详见 §七 |
